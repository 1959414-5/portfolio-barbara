PROJETO DEMONSTRATIVO · DADOS SINTÉTICOS

Portal de solicitações internas.

Uma empresa fictícia precisa registrar chamados, manter histórico e organizar o atendimento de solicitações relacionadas a sistemas corporativos.

O problema

Solicitações espalhadas por canais diferentes tornam difícil acompanhar responsáveis, prioridades, status e histórico de atendimento. O portal propõe um único fluxo com regras claras.

Escopo didático: esta é uma aplicação demonstrativa. Não é um sistema corporativo em produção e não contém dados reais de usuários ou empresas.
CadastroConsultaAtualização de statusHistórico

O que demonstra

  • API REST
    Endpoints para cadastrar, listar, consultar e mudar status das solicitações.
  • Persistência
    Entidades relacionadas, repositório Spring Data JPA e banco H2 para desenvolvimento.
  • Regras e validação
    Campos obrigatórios, prioridades e transições de status com mensagens de erro.

Arquitetura resumida

Responsabilidades divididas em camadas para facilitar leitura e manutenção.

Fluxo de uma requisição

Cliente HTTP / Interface web ↓ SolicitacaoController ↓ SolicitacaoService ↓ SolicitacaoRepository ↓ Banco H2 (desenvolvimento) ↓ Resposta HTTP / JSON

Regras principais

  • Uma solicitação nasce com status ABERTA.
  • O status só pode mudar segundo as transições documentadas.
  • Alterações de status geram um registro de histórico.
  • Identificadores inexistentes retornam erro HTTP adequado.

Como executar localmente

O recrutador pode clonar o repositório e testar a API. O site estático não executa o backend diretamente no GitHub Pages.

  1. Instale um JDK compatível com a versão indicada no README e o Maven.
  2. Clone o repositório e entre na pasta projects/ads.
  3. Execute mvn test para rodar os testes automatizados.
  4. Execute mvn spring-boot:run e abra http://localhost:8080.
  5. Use os exemplos em docs/requisicoes.http ou a coleção Postman para testar os endpoints.
